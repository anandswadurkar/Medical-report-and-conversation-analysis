# Project rules: medexplain

The workspace ground rules (`../CLAUDE.md`) apply. These add rules for a tool whose
readers are patients, not researchers.

- **Explain, never diagnose.** No feature may output a diagnosis, a prognosis, a risk
  percentage or a treatment recommendation. Questions for the care team are the output.
- **No built-in normal ranges.** Lab results are judged only against the range printed in
  the uploaded document (ground rules section 2: read metadata from the source). Adding a
  default range table needs an explicit decision recorded in the README.
- **A negated mention must never be shown as a concern.** Any change to `negation.py`,
  `terms.py` concern flags or `glossary.py` matching keeps the negation tests passing and
  adds a known-answer case for the change.
- **Nothing leaves the machine without preview and consent.** `ui.py` must keep the order
  preview, consent tick, send, and must revoke consent when the previewed text changes.
  The offline path must never import `anthropic`.
- **Real patient documents never enter the repo**, including as test fixtures. Tests use
  the synthetic samples or text written inside the test.
- **Glossary definitions** are plain language (about 6th-8th grade), say what a word
  *usually* means, and are checked against MedlinePlus or RadiologyInfo.org.
- The notebook is generated by `tools/build_notebook.py`; edit the script, then regenerate.
